Realtime (protocol v1)#

The server speaks a command/event protocol on /ws?protocol=1. Commands are acknowledged once the work is committed; events are pushed for the channels you can see, in order per channel, at least once. ProtocolClient handles correlation, idempotent retries, duplicate events and recovery after a gap or a reconnect.

async with client.realtime() as live:
    live.watch(channel_id)
    await live.create_message(channel_id, "hello")
    async for event in live.events():
        print(event.name, event.data)

Retrying a send#

create_message takes a nonce (generated when omitted). Retryable failures are retried with the same nonce, so a message the server did commit is never posted twice.

Recovery#

Each event carries a per-channel sequence number and the server’s epoch. A gap, or a new epoch after a server restart, makes the client call events.resync for that channel and report the server’s recent messages to on_resync. After a reconnect the channels added with watch are caught up the same way.

API#

Async client for the Pufferblow command/event protocol (v1).

One websocket carries everything: you send commands (message.create, message.edit, …) and get an acknowledgment once the work is committed, and the server pushes events (message.created, …) for the channels you can see. The client handles the parts that are easy to get wrong: matching acks to commands, safe retries with an idempotency nonce, dropping duplicate events, and catching up with events.resync after a gap or a reconnect.

Example

async with ProtocolClient(auth_token, "https://chat.example.org") as client:
    async for event in client.events():
        if event.name == "message.created" and event.data["content"] == "!ping":
            await client.create_message(event.channel_id, "pong")
class pypufferblow.realtime.ProtocolClient(auth_token: str, instance: str | None = None, *, command_timeout: float = 15.0, on_event: Callable[[EventFrame], Awaitable[None] | None] | None = None, on_resync: Callable[[str, list[ProtocolMessage]], Awaitable[None] | None] | None = None, reconnect: bool = True, ping_interval: float = 30.0, max_backoff: float = 30.0)[source]#

A protocol v1 connection that reconnects by itself.

Parameters:

  • auth_token – User authentication token.

  • instance – Instance URL or authority, e.g. https://chat.example.org or localhost:7575.

  • command_timeout – Seconds to wait for an acknowledgment before raising TIMEOUT.

  • on_event – Called for every event that has not been seen before (sync or async function).

  • on_resync – Called with (channel_id, messages) after a gap or reconnect, with the server’s current view of the channel’s recent messages.

  • reconnect – Reconnect with exponential backoff when the socket drops.

  • ping_interval – Seconds between application-level pings (they also re-check the token).

async create_message(channel_id: str, content: str, *, nonce: str | None = None, retries: int = 2) → ProtocolMessage[source]#

Post a message.

The nonce is the idempotency key. Retryable failures (a dropped connection, a timeout, a rate limit) are retried with the same nonce, so a message the server did commit is never posted twice. Pass your own nonce to retry across calls.

Wire format of the Pufferblow command/event protocol, version 1.

The server’s docs/protocol/v1/fixtures/*.json are the contract; tests/fixtures/protocol_v1 holds an identical copy that the test suite parses. Unknown frames resolve to None so a newer server can add frames without breaking an older SDK.

Skips duplicate events (by event id) and notices gaps.

Delivery is at-least-once and in order per channel within one server epoch. Sequence numbers are per channel; the epoch changes when the server restarts, so a new epoch means anything may have been missed.

exception pypufferblow.protocol.ProtocolError(code: str, message: str, *, retryable: bool = False, retry_after: float | None = None)[source]#

A command the server refused, or that never got an answer.

code is one of the server’s codes (PERMISSION_DENIED, RATE_LIMITED, …) or one of three raised locally: NOT_CONNECTED, DISCONNECTED and TIMEOUT. retryable means sending the same command again is safe; for message.create the repeated nonce makes sure the server never posts the message twice.
